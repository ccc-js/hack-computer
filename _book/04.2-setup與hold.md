# 4.2 setup 與 hold：時脈的兩條紅線

## 兩條紅線，方向相反

時序檢查有兩種，防的是**兩種不同的災難**：

```mermaid
graph LR
    subgraph setup 檢查（太快不行）
        A[訊號] -->|必須在下一拍前<br/>穩定 t_setup| B[DFF]
    end
    subgraph hold 檢查（太慢也不行）
        C[新值] -.->|不得在時脈沿後<br/>t_hold 內亂入| D[DFF]
    end
```

- **setup（建立時間）**：資料必須在時脈沿**之前** $t_{\text{setup}}$ 就穩定。
  違反 → 這一拍鎖存到不完整的值。這限制**最長**路徑。
- **hold（保持時間）**：資料在時脈沿**之後** $t_{\text{hold}}$ 內不得改變。
  違反 → 下一拍的資料提前亂入。這限制**最短**路徑。

數學化（本專案 `lib/asic/pnr.js` 註解原文）：

$$\text{setup：}\; T \ge t_{\text{clk}\to q} + t_{\text{comb,max}} + t_{\text{setup}}
\quad\Rightarrow\quad F_{\max} = 1000/T$$

$$\text{hold：}\; t_{\text{clk}\to q} + t_{\text{comb,min}} \ge t_{\text{hold}}
\quad\Rightarrow\quad \text{hold slack} = t_{\text{clk}\to q} + t_{\text{comb,min}} - t_{\text{hold}}$$

| 檢查 | 路徑 | 違反的修法 |
|---|---|---|
| setup | 最長路 | 降頻、切短邏輯、加管線、升級高速單元 |
| hold | 最短路 | **不能降頻解決**——加延遲單元/緩衝器 |

> **工程警語**：hold 違反比 setup 違反凶險。setup 違反正確性隨頻率變化（降頻就活）；
> hold 違反**與頻率無關**——晶片一到手上就是壞的。所以量產前 hold 檢查是絕對紅線。

## 本專案的 DFF 模型

```js
// lib/asic/synth.js — STDCELL
DFF: { area: 8.0, delay: 0.30, setup: 0.15, hold: 0.05, clkq: 0.30 },
```

五個參數對應真實單元庫 .lib 檔的時序欄位：

| 參數 | 值 | 角色 |
|---|---|---|
| `clkq`（=delay） | 0.30 ns | 時脈沿 → Q 輸出（launch 延遲） |
| `setup` | 0.15 ns | 資料須提前穩定的量 |
| `hold` | 0.05 ns | 時脈沿後資料須維持的量 |

FPGA 版（`lib/fpga/pnr.js`）則簡化為兩參數：`dffDelay = 0.6 ns`（clk→q 併入路徑起點）、
`lutDelay = 1.2 ns`。

## AsicPnR 的雙向檢查

```js
// lib/asic/pnr.js — analyzeTiming()（註解原文）
// - setup：時鐘週期 T ≥ max(DFF: clkq + 組合路徑延遲 + setup) → F_max = 1000/T
// - hold：min(DFF: clkq + 最短組合路徑) ≥ hold → hold slack
// - 回溯關鍵路徑（cell id 列表）
```

實作上與 4.1 節同構，只是**同時跑最長與最短**兩個 DP：
- 最長路（setup）：`max(各輸入 arrival)` —— 同 FPGA 版；
- 最短路（hold）：把 `max` 換成 `min`、線延遲取下界。

FPGA 版只做 setup——這是合理取捨：FPGA 的 LUT 延遲（1.2 ns）遠大於 hold 視窗
（0.05 ns 量級），最短路徑天然過關；ASIC 單元延遲小（INV 0.08 ns），
相鄰 DFF 直連時 hold 就真的會緊張，必須檢查。

## 時脈週期的完整帳單

把第 5 章的 ASIC 實測數字代進 setup 公式：

$$T_{\min} = 28.75\;\text{ns（關鍵路徑含 clk→q）}
\quad\Rightarrow\quad F_{\max} = 34.8\;\text{MHz}$$

拆開看這 28.75 ns 裡有什麼：`clkq 0.30` + 組合邏輯 cell 延遲（幾百顆 cell 串聯，
每顆 0.08–0.20 ns）+ 線延遲（0.01 ns/µm × 累積 µm）+ fanout 項（0.02 × 扇出）。
**線延遲佔比高**是拓撲成列（未做事後最佳化）的直接後果——這正是 3.4 節留白的代價，
也是真實流程「時序驅動佈局」存在的理由。

> **理論閉環**：setup 紅線決定「設計能不能用」，
> hold 紅線決定「設計是不是一生下來就壞」。
> STA 的職責就是在流片前把兩條紅線各量一次。
