# 2.2 展平：flattenChip 從 HDL 到 NAND 網表

## 問題：階層是給人看的，不是給機器看的

`CPU.hdl` 裡寫著 `ALU(x[16], y[16], ...)`，`ALU.hdl` 裡又寫著 `Add16(...)`，
`Add16.hdl` 裡是 16 個全加器，全加器裡是 Nand……**階層**讓人類能管理百萬閘的設計，
但最佳化與映射需要的是一張**全域的、位元級的**圖——階層邊界會把跨模組的化簡機會
（例如某模組輸出恆為常數）藏起來。

所以合成的第一步是 **flatten**：遞迴展開所有實例，直到網表裡只剩製造工藝的原子：
**NAND 與 DFF**。

## flattenChip 的遞迴結構

```js
// lib/fpga/synthesis.js
flattenChip(elab, topChip) {
  const gates = [];
  const aliasList = [];
  const primaryInputs = [], primaryOutputs = [];
  const recurse = (chip, prefix, inMap, outMap) => {
    for (const part of chip.parts) {          // 逐個實例
      // 1. 解析這個實例的每個輸入位元接到哪條 net
      // 2. 內建 Nand → 推入 {type:'NAND', in:[a,b], out:net}
      //    內建 DFF/暫存器 → 推入 {type:'DFF', in:[d], out:net}
      //    其他子晶片 → recurse(childChip, childPrefix, ...)
      // 3. 實例輸出 → 記 alias（子 net 別名到父 net）
    }
  };
  recurse(topChip, '', topInMap, topOutMap);
  return { primaryInputs, primaryOutputs, gates, aliasList };
}
```

三個關鍵動作：

1. **路徑前綴**：每個實例的 net 名稱帶路徑（`alu.add16_i3.carry[2]`），
   保證展平後全域唯一。
2. **slice 逐位元**：`x[3]` 這種位元選擇直接映射成 per-bit net；
   `x[0..7]` 是 8 條獨立接線。
3. **alias（別名）**：直通連線（`out=foo` 接到下一層的 `in=foo`）不產生閘，
   只記 `aliasList`，留給 `optimizeGates` 的 `getRoot()` 追根。

## 一個血淚教訓：死閘防禦

展平器最大的坑：**實例輸出未接 Wire 時，elab 的 `resolveOutBitsFor` 回傳 null**。
若照推，網表裡會混進 `out === undefined` 的死 NAND，下游一叫 `short().length` 就炸：

```js
// 教訓（lib/fpga/synthesis.js，register bit 展開處）：
// q[0] 為 null（輸出未接）的 Nand/Dff 必須跳過，不可推入 gates。
```

> **工程啟示**：EDA 工具處理的是別人寫的電路，防禦式檢查不是可選項。
> 真實工具鏈用嚴格的 netlist schema＋lint 層解決同一問題。

## 展平的代價：爆炸

展平消滅了階層，也消滅了結構共用——同一個 `Add16` 用在 3 個地方就展開 3 份。
Hack CPU 的實測：`CPU.hdl` 展平後是 **2,680 顆位元級閘**。
工業界處理爆炸的手段（多層式合成、保留階層做參數化重用）本專案刻意不做——
展平後的單一網表讓後續每個演算法都簡單到可以整個寫進教科書。
