# 4.3 兩套經驗延遲模型：FPGA 與 ASIC

## 延遲模型 = EDA 的單位系統

STA 算的是圖上最長路，但每條邊的「權重」從哪來？來自**延遲模型**——
把物理世界（電晶體開關、電容充放電）壓縮成幾個係數。模型越粗，跑得越快、
數字越不準；模型越細，越接近 SPICE 級的電路模擬，但代價是指數級的計算量。

本專案兩條後端各有一套刻意透明的經驗模型，本節把它們並排解剖。

## FPGA：LUT 延遲＋每格線延遲

```js
// lib/fpga/pnr.js
this.lutDelay  = options.lutDelay  || 1.2;   // ns，每穿過一顆 LUT
this.dffDelay  = options.dffDelay  || 0.6;   // ns，DFF clk→q
this.wireDelay = options.wireDelay || 0.25;  // ns，每單位曼哈頓距離（格）
```

路徑總延遲：

$$t_{\text{path}} = t_{\text{clk}\to q} + \sum_{\text{LUT 沿途}} 1.2
\;+\; \sum_{\text{線段}} 0.25 \times d_{\text{格}}$$

**模型假設**：

- 每顆 LUT 延遲與其實現的函數無關（真值表是 SRAM 查表，物理上是同一組傳輸電晶體）；
- 線延遲只跟**幾何長度**成正比，與 fanout、繞線開關數無關；
- 這兩條假設與真實 FPGA 架構（如 Xilinx 7 系列）定性一致：LUT 延遲在架構文件裡
  確實是常數量級，互連延遲確實主導長線。

**數字合理性**：1.2 ns 對應約 800 MHz 的單級上限、22 MHz 的實測 Fmax 來自
38 級串聯——數量級與老 FPGA 上跑 Nand2Tetris CPU 的實際體驗相符。

## ASIC：cell 延遲＋線延遲＋扇出負載

```js
// lib/asic/synth.js — STDCELL（示意值）
INV:   { delay: 0.08 },
NAND2: { delay: 0.12 },
AOI21: { delay: 0.16 },
MUX2:  { delay: 0.20 },
DFF:   { delay: 0.30, setup: 0.15, hold: 0.05, clkq: 0.30 },

// lib/asic/pnr.js
const WIRE_NS_PER_UM   = 0.01;   // 每 µm 線延遲
const LOAD_NS_PER_SINK = 0.02;   // fanout 負載項
```

路徑總延遲：

$$t_{\text{path}} = \sum_{\text{cell}} t_{\text{cell}}
\;+\; \sum_{\text{線}} 0.01 \times d_{\text{µm}}
\;+\; \sum_{\text{線}} 0.02 \times \text{fanout}$$

**與 FPGA 的兩個本質差異**：

1. **cell 延遲逐類不同**：INV 比 MUX2 快 2.5 倍——標準單元的延遲跟驅動強度與
   內部電晶體網有關；FPGA LUT 則是同質的。
2. **扇出進入模型**：一條線推 8 個 sink 比 push 1 個慢（0.02 × 8 = 0.16 ns 的負載項）。
   這是 Elmore 延遲 $t \approx RC$（$C \propto$ 掛載電容）的最粗影子。
   FPGA 版沒有這一項——繞線開關的延遲被併進常數 0.25 ns/格。

## 同一電路，兩個答案

Hack CPU 在兩套模型下的 STA 結果：

| | FPGA | ASIC |
|---|---|---|
| 關鍵路徑 | 45.55 ns | 28.75 ns |
| $F_{\max}$ | 22.0 MHz | 34.8 MHz |
| 主要延遲來源 | 38 級 × 1.2 ns LUT | 數百 cell × 0.08–0.20 ns ＋ 線延遲 |

> **理論教訓**：Fmax 的絕對值沒有意義，**有意義的是模型**。
> 兩個數字差 1.6 倍，不代表 ASIC 真的快 1.6 倍——只代表兩套模型對
> 「一級邏輯值多少 ns」的定價不同。EDA 教學中最常見的誤區就是
> 把模型輸出當物理事實。真實工具的價值，正在於模型經過矽驗證（silicon calibration）。

## 延遲模型如何回饋上游

延遲數字不只給人看，它驅動整個流程的決策：

- 佈局目標函數從「線長最短」升級為「**時序最壞 slack 最大**」（時序驅動佈局）；
- 合成映射從「面積最小」升級為「在延遲約束下最小」（constraint-driven synthesis）；
- 關鍵路徑上的 cell 換高速單元（ASIC）或加管線暫存器（FPGA）。

本專案把這條回饋線**斷開**（佈局只用線長、映射只用面積），
但把 STA 結果完整輸出——讀者若想做時序驅動擴充，接點已經留好：
把 `analyzeTiming` 的 slack 塞回 `place` 的 cost 函數即可。
