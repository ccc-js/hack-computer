# 2.3 最佳化：optimizeGates 的三式代數

## 最佳化的本質：在等價類裡找最小的

展平後的網表幾乎一定有冗餘：HDL 是人寫的，人會寫出接常數的輸入、自我抵銷的雙重否定、
以及根本沒人用的輸出。`optimizeGates` 的目標是找一個**布林等價但更小**的網表。

形式化地：兩個網表 $N_1, N_2$ 等價，若對每個 PO，$N_1$ 與 $N_2$ 實現的函數相同
（$\forall x \in \mathcal{B}^{n}: f_{N_1}(x) = f_{N_2}(x)$）。
**布林等價檢查（CEC）本身是 co-NP 完全的**，所以實用最佳化都走「局部代數重寫」：
每一步保證等價（代數恆等式），不需要全域驗證。

## 三式恆等式與程式對應

### 式一：常數吸收（domination）

$$\text{NAND}(0, x) = 1,\qquad \text{NAND}(x, 0) = 1,\qquad \text{NAND}(1, 1) = 0$$

```js
// lib/fpga/synthesis.js — optimizeGates 主迴圈
if (g.type === 'NAND') {
  if (in0 === '0' || in1 === '0') {        // 有一腳接常數 0
    alias.set(g.out, '1');                 // 輸出恆為 1
    changed = true;
    continue;                              // 這顆閘消失了
  }
  if (in0 === '1' && in1 === '1') {        // 兩腳都接常數 1
    alias.set(g.out, '0');
    changed = true;
    continue;
  }
}
```

### 式二：雙重否定（involution）

$$\overline{\bar{a}} = a \quad\Longleftrightarrow\quad
  \text{NAND}(a,a) \text{ 的輸出再經一顆 } \text{NAND}(y,y) \text{ 時直接接回 } a$$

程式裡它藏在 **alias（別名）機制**：一顆閘被化簡時不刪除，而是記
`alias.set(g.out, 根net)`；之後每個讀到這條 net 的閘，先用 `getRoot()` 追到真源頭。
這種「**lazy 刪除**」的寫法讓主迴圈不用處理複雜的圖編輯。

### 式三：死碼清除（dead code elimination）

主迴圈從頭到尾都會**重建 gates 陣列**（`nextGates`），沒有被任何 PO 或 DFF 輸入
可達的閘自然不再被推入——恆等式是「無人引用即無存在」。

## 不動點迭代

一顆閘化簡後，它的消費者可能也變成可化簡（連鎖反應）。程式用最樸素也最穩的
**work-list 不動點迭代**：

```js
let changed = true;
while (changed) {
  changed = false;
  /* 掃一遍全部閘，能化簡就化簡並記 alias */
}
// 收斂 = 整輪掃描沒有任何改動
```

每次掃描 $O(|G|)$，最多迭代 $O(|G|)$ 輪（每輪至少少一顆閘），最壞 $O(|G|^2)$——
對千顆級的電路毫無壓力，這是「小到能看懂的演算法」的典型取捨。

## 為什麼只有三式？——局部 vs 全域

真實合成器還有：共同子表示式抽取、rewriting/resubstitution（AIG 重寫）、
兩層式 SOP 最小化（espresso）……本專案只留三式，是刻意的教學取捨，
但它們恰好覆蓋了本專案語料裡最大的兩筆化簡收益（見第 5.4 節實測）：

| 晶片 | 展平 | 化簡後 | 減幅 | 主力恆等式 |
|---|---|---|---|---|
| Inc16 | 384 | 224 | −42% | 常數吸收（進位鏈端點恆定） |
| PC | 912 | 640 | −30% | 常數吸收＋死碼 |
| ALU | 1,278 | 1,174 | −8% | 少量 |
| And/Mux/DMux 系列 | — | — | 0% | 無冗餘可化簡 |

> **理論教訓**：化簡收益完全取決於**電路怎麼被寫出來**。
> 結構良好、無冗餘的設計（And 系列）給最佳化器留下零空間；
> 「化簡空間」是設計風格的影子，不是演算法的功勞。

## 驗證：測試怎麼保證等價

`test/test_syn_pnr.js` 對多顆晶片做**逐 net 等效比對**（以 NAND 參考網表為黃金模型），
本質上是手工版的功能等價檢查。工業界的對應物是 formal equivalence checking
（如 Synopsys Formality）——用 SAT/或 BDD 全域驗證。本專案規模小，逐例比對夠用。
