1. RISC-V 的兩個身分

本專案裡 RISC-V 出現兩次，角色完全不同：

  • 軟體這頭（編譯目標）：Jack 程式經 jack2vm 變 VM 碼後，vm2riscv 把它翻成 RV32 組語，跑在 rvemu 模擬器上——這是「程式跑在哪」的問題。
  • 硬體這頭（被造物）：Riscv32i/rv32i.hdl 是本目錄自研的單週期 RV32I 處理器，用 Nand2Tetris 的 HDL 疊出來、被 hdl2js 編譯模擬——這是「CPU 本身怎麼造」的問題。
同一個指令集架構（ISA），一邊當編譯後端、一邊當硬體藍圖。這正是真實半導體世界的分工：ISA 是合約，編譯器與處理器各自履約。

2. 完整一圈路線圖

軟體路（程式的旅程）： .jack ──jack2vm──▶ .vm ──vm2riscv──▶ .s ──rvasm──▶ 機器碼 ──rvemu──▶ UART／螢幕鏡像 硬體路（CPU 的旅程）： Riscv32i/*.hdl ──hdl2js──▶ JS 電路 ──.tst tick/tock──▶ rv32i.cmp 比對 合流點（EDA）： *.hdl ──MicroSyn──▶ NAND 網表 ──▶ LUT4+DFF ──MicroPnR──▶ 佈局＋繞線＋STA 第三塊（Hack 原生路）： .jack ──▶ .vm ──▶ .asm ──▶ .hack ──▶ hackemu（ch05 CPU 硬體跑 Hack 機器碼）

本書沿「軟體→硬體→EDA」的順序走一圈，把四本書的知識串起來。

3. vm2riscv：VM→RV32 後端

lib/riscv/vm2riscv.js 把 VM 碼翻成 RV32 組語（目標＝third_party/rvtools 的 rvasm 子集：真指令＋li/mv/j/jr/ret/call）。兩個關鍵設計：

  • 只用數字版 li：位址全可控、小常數只佔 1 格；符號版佔位不一致的坑已在上游修掉，但後端刻意不用。
  • return 地址走 ra 壓幀：callee 序幕 sw ra, -20(s2) 回填，返回 jalr x0, 0(t1)。
cli 三步（輸出在前）
node cli/vm2riscv.js out.s in1.vm in2.vm  # 多檔才寫 bootstrap（OS 在前）
node cli/riscv_run.js out.s --max 200000  # 組譯＋定步跑，印 ra/s1/a0＋STATIC＋UART
strict vs lenient：未定義 OS 呼叫在嚴格模式 throw（可組譯的產物才保證正確）； translate(files, { lenient: true }) 是顯示模式（照發 jal 並列外部表頭，僅供檢視）。 結尾會檢查每個 call 都有對應 function。

4. 記憶體約定與內聯

VM 的抽象段（SP/LCL/ARG/THIS/THAT/heap/static）在 RV32 的 byte 位址世界裡有固定落點：

VM 資源RV32 位址備註
SP（s1）0x1C000 起向上暫存器 s1 全程持有
LCL/ARG/THIS/THATs2..s5幀指標四兄弟
temp0x10000＋4iVM temp 0..7
static0x11000＋檔序*0x400＋4i≤32 檔、每檔 ≤256 個
heap／SCREEN／KBD0x20000＋4W／…／0x38000Jack word 位址 W 經 this/that 映射

內聯是效能關鍵：

  • Math.multiply/divide → 硬指令 mul/div（RV32M）。
  • Output.printChar/printInt/println/printString → UART ecall a7=1（void 照推 0）。
  • Keyboard.readChar/readInt 不內聯：rvemu 無鍵盤會空等；非阻塞的 keyPressed 可用（rvemu.html 按鍵注入 KBD 鏡像）。
真值約定：true＝-1（Hack 文化）；整數走 32-bit 語意（Hack 原生 16-bit，小數值範圍內一致）。

5. rvtools：rvasm＋rvemu

third_party/rvtools（上游 riscv/_web_tools）提供四件套：isa.js（編碼表）、rvasm.js（組譯器）、rvdis.js（反組譯）、rvemu.js（模擬器）。tools/embed.js 把它們包成 RvToolchain IIFE（window.HackRv）給網頁用。

💡 動手玩：rvemu.html#prog=Pong&run=1 → 三欄介面（編輯／機器碼／螢幕）；可單步（PC 高亮）、重設、速度滑桿 0..100 對應約 316..10 萬步/幀；上限填 0＝無限跑（遊戲永不 halt）。
💡 jack.html 的 RV 後端：jack.html#prog=Seven&backend=riscv → RISCV 分頁看模組的 lenient 預覽；「▶執行」＝嚴格翻譯→rvasm 組譯→rvemu 跑滿 200 萬步（Pong 光初始化就要約 100 萬步）。

6. Riscv32i：用 HDL 造 CPU

現在換帽子：不編譯程式了，造 CPU 本身。Riscv32i/rv32i.hdl 是單週期 RV32I（word 定址），資料通路五段在一次 eval 內做完：

Riscv32i/rv32i.hdl — 摘錄（完整檔見語料章節「06 RV32I 處理器」）
CHIP rv32i {
    IN  dbgRd[5];                // 除錯探針：選讀任一暫存器
    OUT pc[32], dbgReg[32];
    PARTS:
    // IF：PC → ROM32 取指
    R32(in=pcNext, load=pcLoad, out=pc);
    ROM32(address=pc[0..14], out=instr);
    Add32c(a=pc, b=one,  cin=false, out=pcSeq);
    Add32c(a=pc, b=imm,  cin=false, out=pcTgt);
    // ID / EX / MEM / WB：RvDec → RF32 → RvAlu/RvBr → RAM32W → 寫回
}

▲ 一週期一條指令；HALT（opcode 1111111）黏住 halted 凍結 PC。

子晶片分兩層：

層晶片
32-bit 積木（本目錄自有）Add32c／And32／Or32／Xor32／Not32／Mux32／Mux4Way32／Cmp32／Eq32／Se12／Se20／SImm／Ui32／Zero32i
處理器器官（源自 Riscv32/_lib 拷貝）R32（PC）／RvDec（解碼＋ctl[15:0]）／RvAlu（11 種運算）／RvSh32（桶式移位）／RvBr（六種分支）／RF32／RAM32W／ROM32（內建）
閘級基礎複用課程 ../01、../02（Nand 一直往下到底）
💡 動手看：hdl.html#case=Riscv32i/rv32i → hdl.html 語料選單切到「06 RV32I 處理器」；逐層點開電路圖看 rv32i 怎麼由子晶片組成。

7. 指令集與 word 定址

支援範圍（與 Riscv32/RV32S 相容的簡化）：

類指令
R 型（10 種全）add／sub／sll／slt／sltu／xor／srl／sra／or／and
I 型addi／slli／srli／srai／slti／sltiu／xori／ori／andi
載存LW／SW（word 定址）
跳轉LUI／AUIPC／JAL／JALR
分支beq／bne／blt／bge／bltu／bgeu
停機HALT（opcode 1111111）
word 定址的代價與收穫：省掉 LB/LH/LBU/LHU/SB/SH 與 FENCE/ECALL；jump 目標不斷 LSB（byte 版 RV 回跳恆偶數、清 LSB 無害，word 版奇數 PC 合法——JALR 若照抄 & ~1 會跳錯一格，這是 rv32i.hdl.md 記下的除錯血淚）。

8. .tst 驅動硬體 CPU

硬體 CPU 的驗證走 .tst 腳本：載入 rv32i.hdl、ROM32 load 程式、tick/tock 逐週期推進、經 dbgRd 探針與 RAM32W[i] 讀狀態，與 .cmp 逐行比對。

Riscv32i/sum10.tst — 摘錄
load rv32i.hdl,
output-list pc%X1.8.1 dbgReg%D1.10.1 RAM32W[16]%D1.10.1 time%S0.6.1;
ROM32 load sum10.hack,
set dbgRd 1,
repeat 45 { tick, tock, output; }   // 45 週期跑完 1+2+…+10

▲ sum10：sum=55 存 mem[16] 再讀回；HALT 後 PC 凍結在 9。期望值 x1=55、x2=11、x3=10（見 sum10.asm 註解）。

CLI 全套（60 指令綜合測資）
node cli/hdl2js.js --dir third_party/courses/01 --dir third_party/courses/02 \
  --dir third_party/courses/03/a --dir third_party/courses/03/b \
  --dir third_party/courses/05 --dir Riscv32i --test Riscv32i/rv32i.tst

▲ rv32i.tst：60 指令跑完 32 個暫存器全中（rv32i_prog.asm 註解列期望值）。

9. 從 .asm 到 .hack

硬體 CPU 的測資程式由 Riscv32i/*.asm 經 third_party/courses/Riscv32/asm.js 組譯成 .hack（供 ROM32 load，CLI 與 web 共用格式）：

Riscv32i/sum10.asm — 開頭
        addi x1, x0, 0            # 0  sum=0
        addi x2, x0, 1            # 1  i=1
        addi x3, x0, 10           # 2  n=10
loop:   add  x1, x1, x2           # 4  sum+=i
        addi x2, x2, 1            # 5  i++
        blt  x2, x4, loop         # 6  i<11 則續跑

▲ 同一份 .asm 精神也餵軟體路（vm2riscv 產物走 rvasm）；兩邊組譯器各自獨立但 ISA 一致。

10. 接上 EDA：合成數據

最後一站：把 HDL 電路交給本專案的迷你 EDA（lib/fpga/synthesis.js 的 MicroSyn：NAND/DFF 展平 → 化簡 → LUT4 techmap；MicroPnR：退火佈局＋繞線＋STA）。實測數據（node 直跑 synthesize()）：

頂層rawGates（化簡後）LUT4DFF
RvAlu（11 種運算）5,2548850
RvSh32（桶式移位）1,8583310
RvBr（六種分支）1,9582230
RvDec（解碼器）1,9302040
CPU（ch05 Hack）2,22434448
rv32i 本體為何不在表上？它引用黑盒記憶體（RF32／ROM32／RAM32W 內建原語）， MicroSyn 展平到閘級時會拒絕黑盒（「暫不支援內建黑盒子記憶體」）。 要合成 rv32i，得先把這三顆也用 HDL 展開——這正是 project 05 的 CPU 為何能進表：它的 ROM32K/RAM16K 在測資層代換，展平時只剩純閘。
💡 動手看：hdl.html#case=Riscv32i/RvAlu → 按「合成 LUT」看 RvAlu 的 ①展平 ②化簡 ③FPGA 映射 退火佈局到 STA 全流程。
四書合流：軟體書（Jack→VM→asm）產生程式；硬體書（HDL→tick/tock）造出跑程式的機器；EDA 書（gate→LUT→佈局）把機器變成晶片；本書把它們接成一圈。

11. 小測驗

Q1. vm2riscv 為什麼只用數字版 li？
✔ A。符號版 li 的佔位不一致雖已修（固定 lui+addi 2 格），後端仍刻意用數字版求位址確定與省格。
Q2. Jack 的 heap 寫入在 RV 路徑落到哪？
✔ A。0x1C000 是 SP 起點、0x11000 是 static；heap／SCREEN／KBD 的 Jack word 位址 W 映射到 0x20000＋4W。
Q3. rv32i 的 JALR 為何「不斷 LSB」？
✔ B。byte 定址指令恆 4-byte 對齊故回跳恆偶；word 定址 1 word＝1 指令，link＝35 這種奇數是合法目標。
Q4. sum10.tst 用什麼觀察執行結果？
✔ B。硬體 CPU 的除錯介面：dbgRd[5] 選暫存器、RAM32W[i] 探記憶體；輸出走 .cmp 比對。
Q5. 為什麼 EDA 合成表上沒有 rv32i 本體？
✔ B。子晶片（RvAlu 等）都是純閘所以能合成；把記憶體黑盒也用 HDL 展開後 rv32i 才能整顆下場。

12. 名詞表

ISA
指令集架構：軟硬之間的合約；本書主角 RV32I 在本專案同時當編譯目標與硬體藍圖。
vm2riscv
VM→RV32 後端（lib/riscv/vm2riscv.js）；只用 rvasm 子集，strict/lenient 兩模式。
rvtools
third_party/rvtools 四件套：isa/rvasm/rvdis/rvemu；embed 後為 window.HackRv。
word 定址
rv32i 的記憶體簡化：1 位址＝1 word（32-bit）；放棄 byte/half 存取。
HALT
opcode 1111111：黏住 halted、凍結 PC；rv32i 的停機約定。
dbgRd / dbgReg
rv32i 除錯探針：5-bit 選讀 32 個暫存器之一。
RvDec / RvAlu / RvSh32 / RvBr
處理器四器官：解碼／11 種運算／桶式移位／六種分支。
黑盒記憶體
RF32/ROM32/RAM32W 等內建原語；MicroSyn 不展平黑盒，故 rv32i 本體暫不可合成。
ecall a7=1
RV 路徑的 UART 輸出約定；Output.print* 內聯後的物理出口。
