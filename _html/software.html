1. 軟體線是什麼？

Nand2Tetris 的後半程（projects 06–11）是軟體這一半：我們自己寫編譯器和OS，把程式掉到一台自建電腦（Hack 機／RV32 機）上跑。本系統把它全部重寫成 JavaScript 工具鏈：

你寫的 Main.jack → 被編成 VM 碼（jack2vm）→ 被翻成組語（Hack 或 RISC-V）→ 被組成機器碼 → 跑在模擬器上。所有中間分鋪物都真實可看，不只視覺結果（遊戲／輸出），還能看每一格 mem、每個 cycle。

2. 兩條執行路徑

主路徑（HackCPU）： .jack ──jack2vm──▶ .vm ──vm2asm──▶ .asm ──hackasm──▶ .hack/.bin ──hackemu──▶ 螢幕/鍵盤/UART 第二路徑（RISC-V）： .jack ──jack2vm──▶ .vm ──vm2riscv──▶ .s ──rvasm──▶ bytecode ──rvemu──▶ 螢幕鏡像/STATIC/UART 兩路徑共同：前端 Translator「JackParser→Semantics→VM Writer」皆由 lib/jack/* + lib/vm/*（共用）。

jack.html 頁首可切 backend=hackcpu|riscv，兩邊分頁獨立各有自己編譯器＋模擬器分工（jack.html）。

3. Jack 語言與符號表

Jack 是一個「教學娃娃任務語言」但有完整 OOP：class/field/static/function/method/constructor。前端 Parser＋語意階段首件大事是符號表：

lib/jack/ast.js（摘錄）
// 符號表分兩層：class 級（static/field）與 subroutine 級（argument/local）
this.classSymbols = [];
this.subroutineSymbols = [];
// lookup 依 scope 由小到大：arg → local → field/static → class
const find = (kind) =>
      this.subroutineSymbols.find((s) => s.name === name) ||
      this.classSymbols.find((s) => s.name === name);

▲ 編譯器對 VarRef 能解析型別和 offset 全靠兩層符號表；最終 VM 指令如 push this 3 的 3 就是這裡算出來的 field 槽位。

kindsegmentstar 生活
argumentargument呼叫者 push 順序傳入
locallocalfunction 內宣告
fieldthis物件概念、堆積（heap）
staticstatic類別層自由變數（static pool）

4. jack2vm：語意→VM

cli/jack2vm.js 是前端編譯器（輸出在來源旁 output/）：算到 .jack → .vm 純文字 VM 碼。每一行 VM 行都會在 VM 轉出處帶回註記，本系統會在每行前加 # <原 Jack 行>，方便對照。

lib/jack/jack2vm.js — 表達式鍵（概念摘錄）
// let x = x + y; 大致構進為:
push this 0      // x
push local 0     // y
add
pop this 0       // let 回存

// if/while 都編到 goto/Label 兩段；呼叫編到 call 指令；
// "return this" 左到 hint this。

▲ Jack 是「無 OS 就能跑」的語言：本系統讓 jackNoOs 系列程式（如 Sum/Fib）不 GET OS 全量也能 run。

💡 動手看：../dist/jack.html#prog=Sum →
.vm 分頁邊編側看 VM 碼自動出現；想對比 ToVmWriter 生成語法可以按「▶執行」。

5. VM 碼的 8 條句法

本系統實作了 Jack VM 的完整指令表，探最核心 8 條：

分類指令在本系統的實作檔
固定記憶push/pop × {argument, local, this, that, temp, static, constant, pointer}lib/vm/
算術add/sub/neg/eq/gt/lt/and or/not全部映射 Hack/RV 指令
分支label/goto/if-gotoD 旗標（Hack）／beq bne（RV）
呼叫function/call/returnrgn 動態標籤＋幀
幀與堆積約定：s1=SP（0x1C000 向上）、s2..s5=LCL/ARG/THIS/THAT、static 走固定地址 0x11000、heap 在 0x20000（RV 路徑）。更多細節請看 README 與 lib/riscv/vm2riscv.md。

6. vm2asm：寫真 Hack 組語

lib/vm/vm2asm.js 是 VM→Hack 組語後端：每條 VM 指令會照實吐出等價 Hack 指令（不是 macro），常用的 push/pop/算術各有標準 Hack 指令序列。模組多檔時會自動加 bootstrap（呼叫 Sys.init）。

cli 層三條命令分工
node cli/jack2vm.js #   .jack → output/*.vm
node cli/vm2asm.js  #   .vm[...] → out.asm（輸出在前；多檔才寫 bootstrap）
node cli/hackasm.js #   out.asm → .hack + .bin

▲ 三段全部獨立可跑；每段都有測試：test/test_vm2riscv.js（42 題）與 README 的 Sum 5050 場景。

💡 動手看：jack.html#prog=Sum → .asm 分頁即（你所想的 Hack 組語）經 key tick 由 vm2asm 生成。

7. hackasm 與 hackemu

hackasm 和 hackemu 是終端接 tapp：組語→機器碼（.hack 十六進位＋.bin 二教位）；模擬器 headless 鏡行，可 --max／--dump 指定站數和 RAM 區段、可 --keys 鍵盤記錄、可 --trace 追踪。

README 的 Sum 場景（CLI 串法）
node cli/vm2asm.js  /tmp/Sum/sum.asm /tmp/Sum/output/Main.vm /tmp/Sum/output/Sys.vm
node cli/hackasm.js /tmp/Sum/sum
node cli/hackemu.js --headless /tmp/Sum/sum.bin --max 500000 | grep "RAM\[16\] static"
# RAM[16] = 5050（1+2+…+10）

▲ headless 模擬器步數上限 10 萬（預設），打印用 RAM[ 前綴；Web 版 index.html 是互動版有三欄 UI、單步高亮、RAM/螢幕/鍵盤 互動。

💡 動手玩：index.html#prog=Pong → ▶執行，鍵盤左右打起來能看到 hackemu 的鍵盤鏡像反應。

8. OS 的角色

Jack 的 OS 是也是一堆 .jack（Math/Output/Keyboard/String/Array…8 檔，gen/os_src），「編進 VM 全量再一起跑」＝OS 也是被成見到記憶體的普通程式。

  • printInt / printString：在 Ras 路徑已被內聯成 UART（ecall）。
  • Math.multiply/divide：RV 路徑映射成 mul/div 硬指令。
  • Keyboard.readChar：在互動模擬器有鍵盤鏡像，headless 是恆 0 需 --keys。
gen/os_src/Output.jack（摘錄：printInt 的主體）
// printInt 是 OS 的打印任務，內聯成 UART 指令（Rub 路徑的 instant inlining）
// 這樣 OS 全量即使被眾多 Jack 呼叫、也以硬體速度傳輸。
💡 動手看：jack.html#prog=Pong&backend=riscv&run=1 →
OS 全量嚴格翻譯跑滿 200 萬步；「▶執行」會送全量 .s 到 RISCV 模擬器，方向鍵可玩 Pong。

9. 第二路徑：vm2riscv

同一分段的 .vm，cli/vm2riscv.js 可以翻出 RV32 組語。兩種風格：

目標LEMMA
rvasm（RV32I+M 子集）真指令＋li/mv/j/jr/ret/call；註解 #
靜態/暫存器s1=SP、s2..s5=frame、heap 0x20000（Jack word 經 this/that 映射）
預先檢查call 需有 function；strict 失敗 throw、lenient 預覽照發 jal
終端三步（CLI 串法）
node cli/jack2vm.js  #   Pong 目錄 → output/*.vm（含 OS 全量）
node cli/vm2riscv.js #   *.vm → pong.s（OS 在前才寫 bootstrap；輸出在前）
node cli/riscv_run.js pong.s --max 100000 #   組譯＋定步跑，印 ra/s1/a0＋STATIC＋UART

▲ RV 路徑的物理映射想法極簡統一：能內聯的都內聯（乘除、輸出）；Jack 的 word 位址經 this/that 映射為 0x20000+4W，寫入後 RAM 鏡像即時重繪。

💡 動手看：rvemu.html#prog=Pong&run=1 →
RISCV 模擬器可以單步（PC 高亮）、速度滑桿；速度滑桿 0..100 對應約 316..10 萬步/幀，預設即每幀一格可玩。

11. 小測驗

Q1. push this 3 的「3」是編譯器從哪裡算出來的？
✔ A。field/static 符號在 classSymbols 依宣告順序編槽位。
Q2. vm2asm 多檔輸入才產生 bootstrap 開場，為什麼？
✔ A/B 兩句路線差異：bootstrap 是多檔聯結（含 OS）的載入約定；單檔的無 OS 程式（Sum/Fib 系列）直接跑。
Q3.jackNoOs 程式（Sum/Fib/GCD…）為何能在 RV 路徑靜態跑、不出 UART 輸出？
✔ B。Sum 5050 存 static／RAM 由模擬器讀回比對；用 Output 的程式在 RV 路徑需要 OS 在前（見第 10 章答案）。
Q4. 本系統在 RISC-V 路徑上「內聯」了哪些 OS 函數？
✔ A。乘除=硬指令 mul/div，輸出=UART ecall；Keyboard 需物理鍵盤鏡像，readChar 類不內聯。
Q5. 「產物不 halt」的場景（如 Pong），要開哪裡看答案？
✔ B。遊戲類永遠不 halt；以固定步數跑完後讀記憶體（CLI），或在 rvemu 上限填 0 不限步直接玩。

12. 名詞表

VM 碼
Jack 編譯後的中間表示；本系統實作 8 條句法族。
bootstrap
多檔輸入的開場碼：設 SP、跳 Sys.init。
堆積（heap）
Jack 的物件/陣列動態空間；Hack 在 RAM 2048+，RV 路徑在 0x20000。
幀（frame）
call/return 的 argument/local/saved 下落位址；LCL/ARG 指向。
static pool
Jack static 變數的專配角（每 .vm 檔一格）。
UART
輸出通道；RV 路徑上 Output print* 內聯後的物理出口。
PC-free
「盯着 static/RAM 觀察」的驗收文化；本系統語言的不 halt 場景。
lenient / strict
未定義 OS 呼叫的兩種處理：嚴格 throw、預覽照發。
