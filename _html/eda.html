1. EDA 是什麼？

EDA（Electronic Design Automation，電子設計自動化）是把「想要的邏輯」自動變成「能跑的電路」的一整條軟體流水線。真實世界的 Synopsys DC、Cadence Innovus 是上百萬行的巨獸；本系統刻意做了一個能讀懂原始碼的迷你版——全在 lib/fpga/（FPGA 後端）和 lib/asic/（ASIC 後端），每個階段都只有幾百行，邊跑邊畫圖。

你已經寫好的 Mux16.hdl 是規格（描述想做什麼）；EDA 工具負責回答四個問題：
① 攤平成 1-bit 邏輯後長什麼樣？② 哪些閘是多餘的？③ 映射成 LUT 還是標準單元？④ 擺在晶片上哪裡、時鐘能跑多快？

本電子書每個章節 = 本系統的一個階段 + 對應的原始碼摘錄 + 可直接點開的真實範例連結（帶網址 hash 開在 hdl.html 的合成浮層上）。

2. 全流程總覽

.hdl（規格） → ① Elab 章 3 : parseHdl → 階層實例樹 → 依賴圖（含循環偵測） → ② flattenChip 章 4 : 攤平成位元級 NAND/DFF 網表 → ③ optimizeGates 章 5: 常數折疊/死碼清除（FPGA 與 ASIC 共用的「技術無關」段） → ├─ FPGA 分流：④ mapToLut 章 6 → ⑤ SA 退火佈局 → ⑥ 曼哈頓繞線 → ⑦ STA 〔MicroSyn＋MicroPnR〕 → └─ ASIC 分流：④ 圖樣映射 章 8 → ⑤ row 佈局 → ⑥ 線長估計 → ⑦ 經驗 STA 〔AsicSyn＋AsicPnR〕

前端 ①②③ 兩種後端完全共用（在 hdl.html 階段列上就標成 共①②③），第 ④ 步才因「科技」分家——這正是真實 EDA 的術語：technology independent vs technology dependent。

3. HDL → Elab（前端）

lib/hdl/parser.js 把 HDL 文字變 AST；lib/hdl/elab.js 再把 AST 變成晶片庫 + 階層實例樹。關鍵概念：

  • 晶片庫：目錄裡所有 .hdl 各是一個節點，內建原語（Nand、DFF、ARegister…）由 Builtin 表提供。
  • 遞迴展開：CPU 引用 ALU，ALU 引用 Add16… 直到撞到原語為止。
  • 循環偵測：A 用 B、B 用 A 直接報錯，不會掛死。
lib/hdl/elab.js（摘錄）export class Elab {
  constructor(chips, names, top) {
    this.chips = chips;      // idx → Chip（含實例樹）
    this.names = names;      // 晶片名 → idx
    this.top = top;
  }
}

▲ Elab 就是一個雙向查表：拿名字找晶片、拿晶片找它的子實例。

💡 動手看：../dist/hdl.html#case=../02/Inc16 → 按「合成 LUT」→ 第 ① 階段會寫出 top 與 PI/PO 統計；想看階層樹本身可按「檢視電路圖」逐層點入。

4. 展平 flattenChip

Elb 後的實例樹仍是有階層的（ALLOC 名字形如 n_Or16_0/Or_1/notb_5）。flattenChip 遞迴展開，把每個實例的輸入對位、輸出接線統一成全域 net 名，得到一張巨大的位元級表：

lib/fpga/synthesis.js — flattenChip（核心摘錄）
for (const slot of chip.evalOrder) {
  const part = chip.parts[slot];
  if (part.clip.kind === 'Builtin') {
    const b = part.clip.b;
    if (b === Builtin.Nand) {
      const inA = resolveSrcBit(part.inConns[0][0].src, 0);
      const inB = resolveSrcBit(part.inConns[1][0].src, 0);
      const q = resolveOutBitsFor(part, 1);
      if (q[0]) gates.push({ type: 'NAND', in: [inA, inB], out: q[0] });
      // q[0]==null：此 Nand 的輸出沒接任何 Wire——是死碼，不推入
    } else if (b === Builtin.Dff) { … }
  } else recurse(childChip, partPrefix, …);  // 自訂子晶片：遞迴展開
}

▲ 每個閘＝ { type, in[], out } 三個欄位；q[0] 的 null 防禦是修過的真實 bug（CPU.hdl 展平會產 2 顆 out=undefined 的死 NAND，撞壞下游客戶端）。

展平率的直覺：16-bit 晶片 × 每層 ×N 個實例 → Mux16 展平 128 閘、CPU 展平 2,680 閘。閘數暴增是分層級描述的代價，所以第 5 章的化簡很重要。

5. 與製程無關的化簡 optimizeGates

兩種後端在這一步共用：跑固定點迴圈，每輪三件事——alias 追蹤（backpoint 到真正的 driver）、常數折疊（NAND(0,x)=1 全往上游縮）、死碼清除（fanout=0 的閘自動被下一輪丟掉）。

lib/fpga/synthesis.js — optimizeGates（核心摘錄）
while (changed) {
  const nextGates = [];
  for (const g of gates) {
    const in0 = getRoot(g.in[0]);
    const in1 = getRoot(g.in[1]);
    if (g.type === 'NAND' && (in0 === '0' || in1 === '0')) {
      alias.set(g.out, '1'); changed = true; continue;  // NAND(0,x)=1
    }
    if (in0 === '1' && in1 === '1') {
      alias.set(g.out, '0'); changed = true; continue;  // NAND(1,1)=0
    }
    g.in[0] = in0; g.in[1] = in1;
    nextGates.push(g);
  }
  gates = nextGates;
}

▲ 收斂 (fixed-point) 迴圈是所有優化器的骨架：每輪把一個閘吃成常數或別名，改不動為止。

化簡效率取決於電路「寫得多冗餘」：

晶片② 展平後③ 化簡後原因
Inc16384224（−42%）double-NOT 鏈全消
PC912640（−30%）Mux 條件傳播
CPU26802224（−17%）控制訊號常數摺疊
Mux16128128（0%）結構本來就最簡
💡 動手看：點上表晶片連結 → 合成 LUT → 分別按 ② 與 ③，Inc16 會看到方塊少四成、報告列 384 → 224（省 160）。

6. FPGA：LUT4 映射

FPGA 的原料只有兩種：K-LUT（本系統用 K=4）與 DFF。任何 ≤4 輸入的邏輯都被折進一顆 LUT，LUT 的 init 位元串是真值表展開。

演算法是貪婪邏輯錐擴張：從每個輸出往上游收 4-input 錐，塞滿為止；塞不下的節點升級成新 Root 繼續收。

lib/fpga/synthesis.js — mapToLut（骨幹摘錄）
const stopSet = new Set('primary inputs');  // PI 是每顆 LUT 的葉
let cone = [root];
while (cone.length <= 錐上限) {
  for (n of 候選) {
    if (inputsUsed(n) + leafCount(n) > maxLutInputs) // 卡住 → 節點升級 leaf
      leafs.push(n);
    else cone.push(n);
  }
}
// init 真值表：對 2^K 種組合評估整個錐
const init = evaluateCone(cone, leafs, root);   // 位元串 → hex

▲ 摘錄有省略（完整實作在 lib/fpga/synthesis.js mapToLut()）；重點是「錐大小 ≤ K ⇒ 無論函數多複雜，一定塞得進一顆 LUT」。

為什麼 LUT 是 FPGA 的魔法？真值表可以實作任何 ≤K 輸入的函數——NAND 網表結構在映射那刻就「蒸發」了，硬體裡只剩 16-bit 的 init 常數。
💡 動手看：../dist/hdl.html#case=../05/CPU → 合成 LUT → 第 ④ 階段：CPU 會出 344 顆 LUT4 ＋ 48 顆 DFF；點任一 LUT 可看它的 hex 真值表。

7. FPGA：佈局、繞線、STA

映射完只是「知道有哪些元件」，還要知道放在格子上哪、怎麼連線、多快。

⑤ 模擬退火佈局

lib/fpga/pnr.js — 骨幹摘錄
// 成本函數＝Σ HPWL（半周長線長），各 net 的 x-y 界盒寬+高
hpwl = Σ (maxX-minX) + (maxY-minY)
for (const temp of 溫度排程) {
  onSample({ temp, cost });                 ← 退火動畫取樣（hdl.html ▶ 重播）
  swapTwoRandomCells();                     ← 提案：交換兩個隨機 cell
  if (Δcost < 0 || Math.random() < Math.exp(-Δcost/temp)) // 退火接受
    keep();
  else undo();
}

▲ 「先讓壞解也逃走（高溫）→ 慢慢只接受變好（低溫）」就是退火本體；onSample 回呼是 hdl.html「▶ 退火動畫」能重播的原因。

⑥ 曼哈頓繞線

lib/fpga/pnr.js — route(...)
// driver → 水平段 → 垂直段 → sink 的迷宮搜尋；一 net 一 path
const path = [src, {x: src.x, y: dst.y}, dst];   // L 形兩段

⑦ 靜態時序分析

lib/fpga/pnr.js — analyzeTiming(getArrival 摘錄)
const getArrival = (netName) => {
  if (arrivalTimes.has(netName)) return arrivalTimes.get(netName);  ← memo
  const lut = cellMap.get(netName);
  if (!lut) return 0.0;                       // DFF 輸出＝週期起點
  let maxIn = 0.0;
  for (const i of lut.inputs) {
    const arr = getArrival(i);                 ← 遞迴取最慢上游
    const dist =曼哈頓距離(i, netName);
    const t = arr + this.lutDelay + dist * this.wireDelay;  // 1.2ns + 0.25ns/格
    if (t > maxIn) maxIn = t;
  }
  arrivalTimes.set(netName, maxIn);
  return maxIn;
};

▲ 物理模型只有兩個參數：lutDelay（LUT 本身 1.2ns）與 wireDelay（每格曼哈頓距離 0.25ns）。Fmax = 1000 / critical-path。

💡 動手看：../dist/hdl.html#case=../02/ALU → 第 ⑦ 階段，紅色走線與紅框 cell 是 critical path；再按「▶ 退火動畫」重看⑤的收斂過程（HPWL 會越變越小）。

8. ASIC：標準單元映射

ASIC 的原料是標準單元庫，面積/延遲有單位、要付錢。本系統的 cell 庫刻意超小（5 種）：

lib/asic/synth.js — STDCELL
export const STDCELL = {
  INV:   { area: 1.0, delay: 0.08 },
  NAND2: { area: 2.0, delay: 0.12 },
  AOI21: { area: 3.2, delay: 0.16 }, // out = !((a & b) | c)
  MUX2:  { area: 4.0, delay: 0.20 }, // out = s ? a : b
  DFF:   { area: 8.0, delay: 0.30, setup: 0.15, hold: 0.05, clkq: 0.30 },
};

映射是peephole 圖樣重寫：在 NAND 網表上找特定子形狀、換成大 cell 升級：

圖樣撿到的形狀換成省
NOTNAND(x,x)INV面積 2→1
MUX2d=NAND(u,v)，u/v 各自經 INV 鏈補出一對互補訊號MUX211 NAND→1 MUX2＋2 INV
AOI21d=NAND(n1,NAND(a,b)) 且 n1/NAND(a,b) 各被 INV 一次AOI21＋INV面積 6→4.2
lib/asic/synth.js — 決策順序註解（摘錄）
// 兩階段：先全體試 MUX2 圖樣（較大收益、鏈較深，若被 AOI 搶走鏈
// 節點會失敗），再對剩餘未匹配的 gate 補試 AOI21 圖樣。

▲ 「圖樣匹配順序」是真實 EDA（Technology Mapping）的核心工程：搶錯子形狀會讓鄰居無法匹配。

💡 動手看：../dist/hdl.html#case=../02/ALU → 合成 LUT → 階段列左側下拉切「ASIC」→ 第 ④ 標準單元映射：ALU 594 cells（NAND2×127 / MUX2×95 / AOI21×77 / INV×295）、面積 100+ µm²。

9. ASIC：佈局與時序

ASIC 佈局是 row-based：兩圖樣不同、但精神一樣——電路按拓撲 level 成列（DFF 輸出會 reset level），每個 cell 佔的寬度 ∝ STDCELL 的 area；沒有退火、確定式。

為何 ASIC 沒有退火？FPGA 是 free-grid，隨便擺都放得下、要靠退火壓線長。ASIC 的 cell 全要塞進固定列、列寬對齊，工程上先用確定式壓好、再交給更專業的 placer 迭代——這裡刻意保留「能看、能教」的簡化版。

繞線是估的（多層金屬通道路由＋DRC/LVS 是巨獸中的巨獸）：driver↔sink 曼哈頓距離合計；STA 的延遲模型也從「格距」換成「cell＋fanout＋線長」：

lib/asic/pnr.js — delay 延遲模型（概念摘錄）
delay(cell) = STDCELL[cell.type].delay
            + 0.02 * fanout(cell)     // 負載
            + 0.01 * wireUm(cell);    // 估出來的線長（ns/µm）
// 時序路徑分兩段：setup = clk-q + combinational + setup(time)
// hold  = clk-q + combination 的最短路徑 ≥ hold(peer)

▲ 上面的 0.01/0.02 是經驗係數（不是可靠製程參數），holdSlackNs 給 ASIC 視圖的第 ⑦ 階段文報告。

💡 動手看：../dist/hdl.html#case=../02/ALU（ASIC 視圖）→ 第 ⑦ 階段：critical path cell 紅框；側欄點 cell 可看延遲/面積/row。

11. 小測驗

Q1. 為什麼 LUT 映射之後，原來的 NAND 網表可以「忘掉」？
✔ B。LUT 是 truth-table 元件，16-bit init 常數就能表現任何 4 輸入函數；原閘結構在映射後無意義。
Q2. 以下哪一步 FPGA 與 ASIC 完全共用？
✔ B。第 ①②③ 段兩後端完全一樣，A 是 FPGA 專屬、C 是 ASIC 專屬。
Q3. CPU 展平 2,680 閘、Mux16 也展平 128 閘；哪個化簡空間大？
✔ B。CPU 2680→2224；Mux16 結構本來就最簡 0 差異（連結見第 5 章表格）。
Q4. 退火的「接受準則」Δcost<0 || rand < exp(-Δ/temp) 中，temp 下降代表的意義？
✔ B。temp 控制接受壞解的機率——高溫多逃、低溫多收斂，就是退火的本意。

12. 名詞表

netlist（網表）
一堆閘＋net 連線的表；本系統的位元級格式是 { type, in[], out }。
alias / root driver
同一 net 的多個名字；`getRoot()` 會串到真正驅動它的閘。
錐（cone）
從某輸出往上游一路收進來的子電路；LUT 映射＝把錐切成 ≤4 葉的小塊。
HPWL
Half-Perimeter Wire Length，所有 net 界盒半周長總和；佈局成本的標準近似。
STA
Static Timing Analysis，靜態時序分析。不跑模擬、用圖上最長路徑估 Fmax。
setup / hold / clk-q
DFF 三個時序參數，STDCELL 裡都有單位數值。
technology mapping
把「與製程無關的閘」改寫為「能買得到的 cell／LUT」，④ 的本體。
peephole
局部小視窗的圖樣匹配重寫；ASIC 映射用這招找 MUX2/AOI21。
